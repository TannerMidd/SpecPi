The improvement loop

A wishlist that earns every item.

Not a feature dump. Not automatic failure scraping. A small feedback system for gaps that are real, reusable, and still unsolved.

  1. 01
    ×

    Notice

    An existing tool or workaround proves insufficient.

  2. 02
    ◇

    Name

    The reusable gap is described without prompts, code, or secrets.

  3. 03
    ≋

    Measure

    Recurrence, reach, impact, and recency reveal what matters.

  4. 04
    ↗

    Improve

    A selected signal becomes a smallest-change experiment with proof and rollback.

  5. 05
    ✓

    Retire

    Verified gaps leave the queue. Later regressions remain visible without reopening themselves.

The ethos

The agent should help improve the environment it works in.

ZenPi does not quietly rewrite itself. It makes friction legible, requires explicit lifecycle decisions, and turns selected gaps into testable, reversible improvement cards.

Use becomes signal. Signal becomes care. The system gets better without getting noisier.

Built around the loop

Attentive enough to notice.
Explicit enough to trust.

01

Privacy-minimized

Bounded sanitization removes recognizable private patterns. Review local reports before sharing.

02

Evidence-led

Unique tasks and impact outrank novelty, volume, and vague frustration.

03

Human-directed

The wishlist informs change. It never grants itself permission to make it.

The foundation beneath it:

  • focused /zen mode
  • provider-safe delegation
  • isolated browser QA
  • reversible changes
