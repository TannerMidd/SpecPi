The ZenPi ethos

Power does not need to feel noisy.

The best agent setup is not the one with the most machinery. It is the one whose boundaries you understand and whose behavior earns trust over time.

01

Calm by default

A Tea House palette, breathing work indicator, and quiet session ambience keep the interface present without demanding attention.

02

Explicit by design

Planning never mutates. Install, update, and uninstall show their intent and require confirmation before touching your setup.

03

Provider-safe

ZenPi installs strict model inheritance for native children. Trusted project settings take precedence, so the boundary remains visible and inspectable.

04

Evidence over folklore

Files, diffs, tests, and runtime behavior outrank assumptions. Repeated friction becomes measured input for improving the harness.

A small, effective system

Everything has a reason to be here.

ZenPi assembles a focused baseline around Pi. Each layer stays inspectable, replaceable, and bounded.

Interface

The Tea House

A responsive startup glyph, warm low-contrast theme, six-breaths-per-minute work indicator, and a quiet clock create a workspace that feels composed.

Delegation

One model lineage

ZenPi's global inherit-only policy keeps native children on the parent model unless trusted project settings intentionally override it.

Operations

Reversible by construction

Managed blocks, checksums, timestamped backups, atomic writes, and rollback keep changes narrow and recoverable.

  • Plan before mutation
  • Preserve unrelated settings
  • Refuse silent overwrites

Research

Escalate only when needed

Ordinary web tools handle ordinary research. DonSeTch is available on demand for crawling, bot walls, and JavaScript-heavy pages.

Workflow

Useful defaults, visible seams

Curated packages, bounded subagent roles, optional shell profiles, and durable working agreements provide leverage without mystery.

The setup learns from friction

A wishlist earned through use.

When the agent encounters a material, reusable capability gap, ZenPi can record a privacy-minimized report. Ranking uses unique-task occurrences and impact, while distinct-session and distinct-project counts show reach—turning vague frustration into a practical improvement queue.

◌

Precision before volume. No automatic failure scraping. Reports are designed to exclude prompts, source code, commands, credentials, and raw project identities, with additional redaction for common sensitive formats.

A boundary you can explain

ZenPi knows what is not its own.

● ZenPi manages

  • Its theme, extensions, and optional skill
  • Its pinned package entries
  • Selected bounded subagent settings
  • Only its marked AGENTS and shell blocks
  • Its manifest, checksums, and backups

○ Always yours

  • Authentication and provider credentials
  • Default provider and model choices
  • Project trust decisions
  • Sessions, missions, and history
  • Unrelated packages and configuration
