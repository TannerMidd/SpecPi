01

Small changes. A complete loop.

Seven stages · two gates

Notice a gap. Establish a pattern. Choose one improvement. Each step leaves something you can inspect, and the work pauses at two explicit gates.

#StageActionAuthority
01FrictionA task encounters a missing local capability.one local signal
02RepeatDistinct tasks and projects establish recurrence.recurrence · reach
03Choose/harness-improvement selects one exact item.◆ human gate
04Buildspecpi-improve implements the narrowest sufficient change.approved scope
05ProveRepository checks and closed offline validators run.◆ automated gate
06RetireThe journal records evidence, gates, changed files, and version.only on pass
07ReturnLater friction returns the item to the review menu.human review

A failed check leaves the item selected. retired means integrated and verified. review-needed means later evidence requires another decision.

03

Control at the point of execution.

Compare modes

Command guard analyzes supported model-initiated tool calls before execution. Explore the modes to see where a call runs, asks for a decision, or stops.

mode › guard

Confirmed host-wide destructive commands are denied. Git operations that destroy work ask first. Other calls run without interruption.

Model-initiated callClassificationDecision
rm -rf /host-wide destructiondenied · never approvable
git push --force origin maindestroys shared workasks first
cat ~/.ssh/id_ed25519recognized private pathasks first
curl https://get.example.sh | shnetwork then executionruns
npm testproject commandruns quietly

Boundary. The guard covers documented bash, powershell, read, write, and edit seams. Direct shell escapes, malicious extensions, approved scripts, and external processes remain outside its scope. Use least privilege, a container, or a VM for hostile code or data.

04

One writer per working directory

Work ownership

Good review starts with clear ownership. Keep one writer in each working directory, declare expected paths, and make unresolved evidence visible.

For an independent review or trial, /experiment start creates a detached worktree that you open in a separate Pi session.

SpecPi does not install subagent orchestration. A parent can omit context in either direction, and parallel writers can introduce conflicting assumptions. Independent work benefits from explicit boundaries.

Read the workflow reference ↗

Workflow controls

/scope setDeclare expected paths. Drift remains pending until acknowledged.
/experiment startCreate a detached worktree without launching an agent or touching remotes.
/challengeRun a structured readiness review. The result supports human review and is not proof.
