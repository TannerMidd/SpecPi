How it works

A control loop,
not an autopilot.

Evidence recommends the work. One human choice starts it; proof—not ceremony—closes it.

01 / signal

Observe locally

Collection begins only after consent. Reusable gaps are sanitized, task-deduplicated, and stored locally—never uploaded.

02 / decision

Choose one change

/harness-improvement opens one clean menu. Choosing an item starts its smallest-sufficient implementation workflow.

03 / outcome

Verify and finish

The harness runs the repository gate and supported validators, then retires only on success. Failures stay selected; later friction returns to the menu.

The goal

Let the environment learn from the work—without taking control from the human.

ZenPi makes friction legible, preserves the evidence, and asks for the smallest intervention that can be proved and reversed.

Use becomes signal. Human judgment turns signal into care. The system gets better without getting noisier.

Built around the loop

Attentive enough to notice.
Explicit enough to trust.

Human-directed

The wishlist informs change. One explicit menu choice authorizes one exact improvement—nothing broader.

# clone a release you have reviewed

cd ZenPi

# Windows PowerShell / Command Prompt
.\zenpi.cmd plan
.\zenpi.cmd install
.\zenpi.cmd doctor

# Linux, macOS, or Git Bash
./zenpi plan
./zenpi install
./zenpi doctor
